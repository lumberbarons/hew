# internal/cli

The CLI adapter for the public workflow packages: `cmd/hew` parses flags, this package reads the inputs the user chose, calls the public operation and renders the result. It is written against the `gh.IssueStore` interface (and `gh.PullRequests`, for `pr` alone, which `App.PRs` leaves nil on a backend with no pull requests) so `cmd/hew` stays pure wiring and every behavior is testable without hitting GitHub. The tracker-shaped reads and the write workflows already delegate to the public `tracker` package — `tracker.Wrap` for reads, `tracker.WrapAs` for `start`/`release`/`close`/`set`/`reopen`/`init`, `tracker.WrapWriter` for `block`/`unblock`, and `tracker.Init` for local initialization — and `pr` delegates its whole workflow to the public `pr` package (`pr.Wrap` over the store the command opened). The migration passes delegate to the public `migrate` engine (`migrate.Wrap` over a `migrate.Target` adapter and the checkpoint the command opened), so this package filters, renders, and maps the library's typed errors onto exit codes rather than owning those behaviors.

Where a row below says a command still calls the client directly or owns a workflow, that is the current implementation, not the boundary. DESIGN.md ("Tracker library") is the operation inventory: it assigns each command's workflow to `tracker`, `pr` or `migrate` and leaves this package flags, input files, the editor, hooks, rendering and exit codes. Moving an operation out means moving its tests and its contract row with it, and no workflow decision stays here once its public operation ships.

| `config.go` | `config`: renders the read-only backend report (`backend`, `repo`, `path`, `id`); resolving the target and opening any store or client is the caller's job | Changing what the config query reports |

Every command reads through the public `tracker` handle the app wraps over its open store (`Snapshot`, `List`, `Get`/`Detail`, `Search`, `Triage`, `Primer`), so this package maps flags, caps sections, renders, and maps warnings and typed errors; no read policy of its own | Changing what a read command returns or how it filters |
| `write.go` | The mutating commands: `create`, `start`, `release`, `set`, `close`, `reopen`, `block`, `unblock`, `epic create`, `init`; label swaps never stack, and `start` uses a backend's atomic claim when it has one, re-reading after the check-then-act path otherwise; `release`, `close`, `set`, `reopen` and the GitHub half of `init` delegate to `tracker.WrapAs`, which owns the ownership check, the atomic release on local stores, the close and reopen guards, the edit field rules, the label bootstrap and the partial-failure errors; `init --local` delegates creation and its notices to `tracker.Init`; `block` and `unblock` delegate to `tracker.WrapWriter`, whose typed refusals (`CycleError`, `ClosedError`, `PartialWriteError`, …) are mapped to the command's text here | Changing a mutation or the claim guard |
| `draft.go` | `draft`: composes an issue body from the section flags, or revalidates a draft file, with no `gh.IssueStore` use — the local counterpart to `create --body-file` | Changing the local body preflight |
| `pr.go` | `pr`: the adapter over the public `pr` package — reads the section flags and `--body-file`, maps them to typed create/amend requests, renders the result's warnings and findings, and spells the library's typed refusals with flag names and exit codes | Changing PR flag handling, rendering, or exit mapping |
| `apply.go` | `apply`: parses the JSONL plan, applies the CLI's field rules and renders `tracker.ApplyPlan`'s result — existing-issue references are looked up before the first write, and an edge that fails to wire exits non-zero | Changing `apply` execution (plan schema and the create/wire pass live in `internal/plan` and `tracker`) |
| `migrate.go` | `migrate beads`: the adapter that maps a parsed beads snapshot onto the conventions (priorities, types, deps, epics, in-progress state) as `migrate.Item`s, opens the checkpoint and drives the public engine, then renders its counts and warnings; label bootstrapping runs as the engine's `BeforeCreate` hook, after provenance verification | Changing the beads migration |
| `migrate_local.go` | `migrate local`: the adapter from a frozen `internal/local` snapshot onto `migrate.Item`s (close reasons, comments with their author credited, claims reduced to the migrating user), `#n` reference rewriting outside code (spans, fenced and indented blocks), the dry-run plan, and the seal that records `.hew/migrated.json` and flips the backend only when every step finished | Changing the local migration |
| `batch.go` | Shared migration machinery: wrappers over the checkpoint schema and file I/O `tracker` owns, label bootstrapping, and the `migrate.Target` adapter over the store the command opened (model issues converted to the engine's public `migrate.Issue` at the boundary). The source-neutral engine itself — create, cycle-checked and checkpointed wire, optional reference relink, checkpointed comments and close — lives in the public `migrate` package | Changing label bootstrapping, the target seam, or migrate's warn plumbing |
| `hooks.go` | `hooks install\|remove`: edits the project's `.claude/settings.json` (claude) or `.codex/hooks.json` (codex) in place, preserving unknown fields; for opencode, writes/removes the whole `.opencode/plugins/hew-prime.js` plugin (go:embed asset in `opencode/`), marker-guarded | Changing the session-start hook |
| `exit.go` | Maps errors to the exit codes agent loops branch on (`2` usage, `3` claimed by someone else, `4` auth, `5` claimed by you, `6` open blockers), plus the `--repo` and issue-number argument parsers | Changing an exit code — it is contract |

Tests run against `fakeClient`, never the network. `batch.go` has no test file of its own — it is covered through the `migrate` commands; the migration engine and its target/checkpoint tests live in `migrate/`, and the apply engine and its checkpoint live in `tracker`, tested there. The provenance marker both verify is unit-tested in `internal/conventions`.

Checkpoint state is trusted local scratch, never a portable input. The schema lives in `tracker/checkpoint.go`; a state file is bound to the repository — or, on the local backend, to the tracker's id from `.hew/config.json`, since a checkout's directory name is neither unique nor stable — and to a digest of its source plan or snapshot, and every issue it maps must carry the provenance marker the batch writer stamped into the body it created — verified in one pass before any write, `--dry-run` included. Tests asserting "no mutation happened" must assert that *only* reads were made (`assertOnlyReads`), not that a list of specific mutating calls was absent: label bootstrapping writes too. See "Checkpoint binding" in DESIGN.md.
