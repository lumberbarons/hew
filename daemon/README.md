# hewd

A local server for the everyday hew workflow: a REST API and a browser UI over a
tracker, local or GitHub, built only on the public `tracker` and `pr` packages. It is
the long-running counterpart to `consumer/`, and experimental like the library it sits
on. It is for one person on one machine (see the security model below).

The Go side is a separate module (`replace github.com/lumberbarons/hew => ../`, like
`consumer/`), so it can name only the public packages. The UI is Vite, React and
TypeScript in `web/`, built into `daemon/dist/` and embedded in the binary.

## Running it

Prerequisites: Go at the version in the root `go.mod`, and Node 24 (what CI uses) to
build the UI. A GitHub-backed tracker also needs `gh auth login`; a local tracker needs
neither `gh` nor a network.

From the repository root:

```sh
make daemon-run                        # build, then serve this checkout (:7777)

make daemon-build                      # builds the UI, then <repo>/dist/hewd
dist/hewd --dir /path/to/a/hew/checkout
# http://127.0.0.1:7777

dist/hewd --dir /tmp/scratch --init-local   # start a local tracker in an empty git checkout
```

`make daemon-run HEWD_ARGS="--addr 127.0.0.1:8080"` passes flags through.

| Flag | Default | Meaning |
|---|---|---|
| `--dir` | `.` | The worktree to serve |
| `--addr` | `127.0.0.1:7777` | Loopback address to listen on; anything else is refused |
| `--repo` | | Force the GitHub backend for `owner/name`, as `hew --repo` does |
| `--init-local` | off | Start a local tracker in `--dir` if it has none |

`--init-local` refuses a checkout whose issues live on GitHub, since a local tracker
beside them would redirect every later `hew` command there to an empty one.

## Layout

| Path | What |
|---|---|
| `server.go`, `handlers_*.go` | Routes, the loopback guard, and the handlers over `tracker` and `pr` |
| `errors.go` | Typed library errors to HTTP statuses and stable `error` kinds |
| `dto.go` | The request body shape and the responses composed from several library results |
| `web/` | The UI: React components in `src/`, unit tests beside them, `e2e/` for the browser specs |
| `web/src/fixtures/` | The daemon's real responses, generated by the Go tests (see below) |
| `daemon/dist/` | The built UI, embedded with `go:embed`; only `.gitkeep` is committed. Not the repo-root `dist/`, which holds the `hewd` binary |

`web/` has its own empty `go.mod`. That keeps Go tooling out of `web/node_modules`,
where some npm packages ship `.go` files; the embedded `daemon/dist/` belongs to the daemon
module.

## Security model

There is no authentication. The daemon is for one person on one machine:

- It refuses any listen address that is not loopback.
- Any web page can make a browser send requests to `127.0.0.1`, so the handler also
  rejects a non-loopback `Host` (DNS rebinding), a foreign or `null` `Origin`
  (cross-site writes), and bodies that are not `application/json` (form-style CSRF).
- Issue text is untrusted. The UI renders it with `react-markdown` and no raw-HTML
  plugin, so tags show as text. Only `http(s)` and in-app issue links are clickable,
  and images are not loaded, since an image URL chosen by an issue's author would be a
  tracking pixel.

## What it covers

Reads: board, ready, list, detail, epics, search, triage, primer, config.
Writes: create, create epic, edit, start, release, close, reopen, block, unblock,
body compose and check, apply (JSON plan), and PR create and amend (GitHub backend).
Library errors map to HTTP statuses with a stable `error` kind: the CLI's exit codes
become `claimed_by_other`, `claimed_by_you` and `blocked` (all 409).

Use **Ideas** to switch between open and closed ideas or select **New idea**
to open the New form with Idea preselected. The list uses the same type filter
as `hew list --type idea`. Open an idea and select **Start investigation** to
claim it. That action sends `forDiscovery: true` with the start request.
The current investigator can select **Release** to give up the claim.

On an open or closed idea, expand **Record outcome**, enter a note, and select
**Save outcome** to append it under `### Outcome` in the issue body.
See the main guide for [recording and linking outcomes](../README.md#recording-an-ideas-outcome).

On a local tracker the `X-Hew-Actor` header (the UI's "acting as" box) picks the
claimant per request through `Tracker.As`. On GitHub every request acts as the
authenticated login.

Not covered: `migrate` workflows (long-running, would need a job model), hooks.

## Developing

```sh
cd daemon/web && npm ci
npm run dev        # Vite on :5173, proxying /api to a daemon on :7777 (HEW_DAEMON to change)
```

Run a daemon in another terminal. The dev proxy presents the daemon's own origin, so
its cross-site guard still accepts writes.

## Testing

| Gate | Command | Floor |
|---|---|---|
| Go: tests, lint, fmt, coverage | `make daemon` | `daemon/.testcoverage.yml`, `cmd/` excluded |
| UI: types, lint, format, unit tests, build | `make web` | thresholds in `web/vite.config.ts` |
| UI: browser end-to-end | `make web-e2e` | specs drive the real daemon and built UI |

CI runs these as the `daemon` and `daemon-ui` jobs. The end-to-end specs need a browser
once: `cd web && npx playwright install chromium`.

**Fixtures are the contract between the two sides.** `web/src/fixtures/*.json` are the
daemon's actual responses for a small deterministic tracker. The Go test
`TestFixturesMatchTheDaemonsResponses` fails when a response changes shape; regenerate
with `cd daemon && go test -run Fixtures -update`. The UI's unit tests render from those
files, each checked against its TypeScript wire type (`web/src/test/fixtures.ts`), so a
changed response then fails the UI's type check or tests where the UI no longer matches.
This caught a real bug when it was introduced: a dry-run `apply` returned
`"mapping": null`.

## Library limits for server use

Where the public library fits a long-running server less well than a per-worktree
agent. None blocks a route.

- **`pr.Client` is bound to one checkout's current branch.** It suits a per-worktree
  agent, not a server fronting many branches.
- **Per-request identity is local-only.** `As` is a documented no-op on GitHub.
- **Plan JSONL codec is internal.** `ApplyPlan` takes typed entries, so the daemon
  defines its own JSON plan shape.
